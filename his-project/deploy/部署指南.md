# HIS 一期部署指南

版本：V1.0 ｜ 适用读者：部署运维人员
配套：《README.md》（工程总览）、《用户操作手册.md》、《06-实施计划与验收对照.md》

> ⚠️ 边界声明（指导文档 §10）：本系统一期定位为**产品原型、内部试点或教学演示**。
> 用于真实医疗业务前，必须另行完成合规评估、渗透测试、灾备设计与医院信息科审批。

---

## 部署方式选择

| 场景 | 推荐方式 | 说明 |
|---|---|---|
| 正式试用 / 长期运行 | **方案 A：Docker Compose**（Linux 服务器或装有 Docker 的机器） | 工程自带全套编排文件，一条命令拉起 5 个服务 |
| 就用当前这台 Windows 服务器（无 Docker） | **方案 B：Windows 原生部署**（注册系统服务 + nginx 托管前端） | 无需安装 Docker，把现有临时进程固化为开机自启服务 |

两种方案的共同前置：**必须修改的默认值**（见 §4 安全清单）。

## 方案 A：Docker Compose 部署（推荐）

### A1. 准备一台服务器

- Linux x86_64（Ubuntu 22.04 / CentOS 8+ 均可），最低 2 核 4G、磁盘 40G。
- 安装 Docker 与 Compose 插件：

```bash
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker
docker compose version   # 确认 v2 可用
```

### A2. 获取工程

```bash
git clone https://github.com/shushi2369/hospital-information-system.git
cd hospital-information-system
```

> 私有仓库：克隆时输入 GitHub 用户名 + Personal Access Token（GitHub → Settings → Developer settings → Tokens 生成，勾选 repo 权限）；
> 或在本机已 `gh auth login` 的环境下直接克隆。

### A3. 构建产物（在任意一台有 JDK17+Maven 和 Node 的机器上执行）

```bash
# 后端 jar
cd his-backend && mvn -DskipTests package
# 产物：target/his-backend-0.1.0-SNAPSHOT.jar

# 前端静态资源
cd ../his-web && npm install --registry=https://registry.npmmirror.com && npm run build
# 产物：dist/
```

> 工程仓库已含最新构建产物时（target/ 与 dist/ 不入库），需按上述命令现场构建。
> 也可以在本机构建后，把 `his-backend/target/*.jar` 与 `his-web/dist/` 拷贝到服务器对应位置。

### A4. 配置环境变量

```bash
cd deploy
cp .env.example .env
vim .env   # 必改以下四项：
```

| 变量 | 生成方式 | 说明 |
|---|---|---|
| `DB_PASSWORD` | 自拟强密码 | MySQL root 密码 |
| `JWT_SECRET` | `openssl rand -hex 32` | 登录令牌签名密钥（≥32 字符） |
| `AES_KEY` | `openssl rand -base64 32` | 身份证加密密钥（32 字节 Base64） |
| `MINIO_PASSWORD` | 自拟 | 对象存储密码 |
| `FLYWAY_LOCATIONS` | 生产**改为** `classpath:db/migration` | **不加载演示数据**（V3 演示账号/科室/药品不进生产库） |
| `SWAGGER_ENABLED` | 生产**必须为** `false` | 接口文档（swagger/api-docs）匿名暴露属高危，默认 true 仅用于开发演示 |

### A5. 启动与验证

```bash
docker compose up -d --build
docker compose ps                      # 5 个服务应为 running/healthy
curl http://localhost/actuator/health  # 经 nginx → 后端，应返回 {"status":"UP"}
```

浏览器打开 `http://服务器IP/` → 使用 **admin / His@2026** 登录 → **立即修改密码**。
生产库首次启动只含 admin 一个账号，科室/医生/药品等基础资料由管理员在界面录入。

### A6. 每日备份（§7 可靠性）

```bash
crontab -e
0 2 * * * DB_PASSWORD=你的密码 BACKUP_DIR=/opt/his/backup /opt/hospital-information-system/deploy/backup/backup-mysql.sh
```

恢复：`gunzip < his_日期.sql.gz | docker exec -i his-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" his'`（恢复后启动应用跑通核心流程验证，演练步骤见 README）。

### A7. 升级流程

```bash
git pull
cd his-backend && mvn -DskipTests package && cd ..
cd his-web && npm run build && cd ..
cd deploy && docker compose up -d --build   # Flyway 自动执行增量迁移脚本
```

### A8. HTTPS（对外访问时必配）

将证书放到 `deploy/certs/`，在 nginx.conf 增加 443 server 块（`ssl_certificate` / `ssl_certificate_key`），compose 里开放 443 端口，并把 80 重定向到 443。

## 方案 B：Windows 服务器原生部署（无 Docker）

适用：就用当前这台机器。目标：把"临时后台进程"固化为**开机自启的系统服务**。

### B1. MySQL 注册为 Windows 服务

当前 MySQL 是命令行临时进程，重启即失。执行（管理员 CMD）：

```bat
C:\his-runtime\mysql-8.0.36-winx64\bin\mysqld --install HIS-MySQL
net start HIS-MySQL
sc config HIS-MySQL start= auto
```

> 数据目录默认取 `C:\his-runtime\mysql-data`（首次启动用 `--initialize-insecure` 初始化，本机已完成）。
> 验证：`mysql -h127.0.0.1 -uroot -p` 能登录 his 库。

### B2. Redis 注册为 Windows 服务

```bat
cd C:\his-runtime
redis-server --service-install redis.windows.conf --service-name HIS-Redis
net start HIS-Redis
sc config HIS-Redis start= auto
```

验证：`redis-cli ping` → PONG。

### B3. 后端注册为 Windows 服务（推荐 WinSW）

1. 下载 [WinSW-x64.exe](https://github.com/winsw/winsw/releases) 改名为 `HIS-Backend.exe`，与 jar 同放 `C:\his-runtime\backend\`；
2. 同目录建 `HIS-Backend.xml`：

```xml
<service>
  <id>HIS-Backend</id>
  <name>HIS Backend</name>
  <description>医院信息系统后端</description>
  <executable>C:\Program Files\Microsoft\jdk-17.0.20.101-hotspot\bin\java.exe</executable>
  <arguments>-Xms768m -Xmx1536m -XX:+ExitOnOutOfMemoryError -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=C:\his-runtime\backend\logs -jar C:\his-runtime\backend\app.jar</arguments>
  <!-- stoptimeout 必须大于 spring.lifecycle.timeout-per-shutdown-phase（application.yml 中 20s）：
       停服时 WinSW 先向 JVM 发 Ctrl+Break 触发优雅停机（Tomcat 等待在途请求），
       超过 stoptimeout 才强杀。不配置时默认 15s，会把 20s 的优雅窗口截断，
       在 net.dll 关闭 socket 时可能触发 EXCEPTION_ACCESS_VIOLATION 崩溃（已实测复现）。 -->
  <stoptimeout>25000</stoptimeout>
  <env name="DB_PASSWORD" value="root123"/>
  <env name="JWT_SECRET" value="改成至少32位的随机串"/>
  <env name="AES_KEY" value="改成 openssl rand -base64 32 生成的值"/>
  <env name="FLYWAY_LOCATIONS" value="classpath:db/migration"/>
  <onfailure action="restart"/>
</service>
```

3. `HIS-Backend.exe install && net start HIS-Backend`。
   jar 更新方式：`bash deploy/deploy.sh`（停服→备份→换 jar→启动→actuator 健康检查→Flyway 巡检）。
   JVM 曾崩溃时先看 `C:\his-runtime\backend\hs_err_pid*.log`；OOM 时自动在 logs 目录落堆转储。

### B4. 前端生产化（nginx for Windows 托管 dist）

1. 下载 [nginx Windows 版](https://nginx.org/en/download.html) 解压到 `C:\his-runtime\nginx`；
2. 用 `deploy/nginx.conf` 的内容替换 `conf/nginx.conf` 的 server 块，但做两处 Windows 化修改：
   - `root C:/his-runtime/frontend;`（把 `his-web/dist/*` 拷贝到此目录）
   - `proxy_pass http://127.0.0.1:8080;`（compose 服务名改为本机）
3. 启动：`nginx.exe`；开机自启：`schtasks /create /tn HIS-Nginx /sc onstart /ru SYSTEM /tr C:\his-runtime\nginx\nginx.exe`（或做成服务）；
4. 验证：浏览器 `http://服务器IP/` 正常打开登录页。

### B5. Windows 侧生产清单

- [ ] 修改 `.env` 等价的环境变量（JWT_SECRET / AES_KEY / DB_PASSWORD），`FLYWAY_LOCATIONS` 仅保留 migration
- [ ] 首登 admin 修改密码；禁用/删除不需要的演示账号（pharm.zhao 等，若生产不用）
- [ ] Windows 防火墙仅放行 80（对内网），3306/6379/8080 **不要**对外开放
- [ ] 用任务计划程序每日 02:00 执行备份脚本（改写为 bat 调 mysqldump）
      ⚠️ 2026-09-21 演练发现：bat 脚本存在但计划任务未注册成功导致备份断裂 5 天——
      注册后必须验证产物（backup 目录出现当日 sql 且含 "Dump completed" 结尾标记）
- [ ] 恢复演练：拿备份文件恢复到临时库验证（步骤见 README）

## 安全清单（两方案通用，上线前逐项打勾）

| # | 项 | 标准 |
|---|---|---|
| 1 | 密钥 | JWT_SECRET/AES_KEY/DB_PASSWORD 全部替换默认值；`.env` 不入库不入聊天记录 |
| 2 | 演示数据 | 生产 `FLYWAY_LOCATIONS=classpath:db/migration`，演示账号与演示药品不进生产 |
| 3 | 密码 | admin 首登改密；所有账号强制 8 位以上 |
| 4 | 网络 | 3306/6379/8080 不对外；对外只暴露 80/443 |
| 5 | 备份 | 每日自动备份 + 异机存放 + 恢复演练通过（2026-09-21 演练：RTO=9s，报告见 deploy/db/drill_report_20260921.md） |
| 6 | 密钥 | 生产启动前设置环境变量 JWT_SECRET（默认 dev-only 值仅限演示环境） |
| 6 | 审计 | 定期抽查操作日志（管理员 → 日志查询） |
| 7 | 边界 | 遵守指导文档 §10：内部试点/教学使用；正式医疗生产前完成合规评估 |
