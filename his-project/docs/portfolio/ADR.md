# 架构决策记录（ADR 摘要集）

> 每条决策都对应仓库里的真实实现与回归测试，可直接面试展开。

## ADR-01 模块化单体而非微服务
- **背景**：医院演示/教学场景，单机部署，团队 1 人。
- **决策**：Spring Boot 单体内分 18 个业务模块；跨模块读写一律经 app 层（InpAppService / ClinicAppService / PatientAppService），模块间禁止直连 mapper。
- **代价与收益**：放弃独立伸缩，换来零分布式事务；app 层即未来拆分的防腐层。

## ADR-02 状态机收敛到 app 层
- 十余条业务状态链（就诊/住院/手术/危急值/传染病）的变更只允许发生在 app 层，controller/service 不直接改状态字段。
- 防线三层：前态校验 → 条件更新（影响行数判定）→ 数据库唯一索引兜底（DuplicateKeyException 转业务错误码）。
- 反例教训：绕过 app 层的直改曾在查验中造成状态分裂。

## ADR-03 幂等键放请求头 + Redis 快照 + DB 兜底
- `X-Idempotency-Key` 请求头（ASCII 纪律），SETNX 存请求摘要，命中返回首次响应快照。
- 业务失败必须释放幂等键（失败不产生幂等语义）；Redis 故障 fail-open，正确性锚在数据库唯一约束（uk_bill_visit 等）。
- 替代方案（DB 唯一表）被否：Redis 路径吞吐更好且快照响应是刚需。

## ADR-04 资金标记收窄 + 残留复查
- 出院结算从"读清单→按 admissionId 全量标记已结"改为"标记收窄到账单包含的费用 ID + 标记后残留复查，有残留同事务回滚"。
- 根因是资损级：结算窗口期新增费用会被标记已结却从未入账单。教训：**"读清单后按父 ID 全量更新"是资损模式**。

## ADR-05 日结按 (日期, 收费员) 建桶并锁定
- 重复日结拒绝（uk_settle_date_cashier → B3006）；锁定语义补全为：本人当日已日结后不得再产生当日交易，否则交易落在任何日结之外。
- 被否方案：允许重生成日结（破坏签发后的报表不可变性）。

## ADR-06 发号器：Redis INCR + 降级号段 + 恢复补偿
- 正常号段 1~500000，降级段 500001+ 物理隔离（防与宕机前历史号撞号）；恢复时若 INCR 回退到本地已发号段之下，补偿 INCRBY 跳过降级段。
- 集群语义下补偿为近似值——诚实标注在注释里，集群以恢复 Redis 数据为准。

## ADR-07 会话放 Redis 且 fail-closed
- 会话读写失败：读→按未登录（401），写→登录失败（C9001）。选择"可用性换即时失效语义"（改密/禁用即踢下线）。
- 停机演练实证：Redis 是认证硬单点；优雅停机持久化使旧会话在恢复后回归。集群化前必须重审（哨兵 + 就近缓存会话的取舍已写入 runbook）。

## ADR-08 权限：RBAC + 数据范围双层，详情与列表同等过滤
- 垂直：261 端点 @PreAuthorize 全覆盖（扫描器固化审计）。
- 横向：收费员数据范围在 bills/refunds/settlements 列表**和详情**都生效——"列表过滤≠详情过滤"（IDOR 教训固化为单测）。
- 前端 v-perm 定位为体验层，安全边界只在后端。

## ADR-09 PHI 脱敏放服务端 toResponse，前端为第二道防线
- 手机号/身份证在响应组装层统一脱敏，身份证哈希列单独建列支撑查重。
- 编辑场景走独立明文通道并留审计——避免"把星号写回数据库"的经典回显陷阱。

## ADR-10 迁移只增不改 + 失败重放防护
- Flyway V1~V38；任何已执行迁移 checksum 不可动。
- 教训：迁移失败重放时已成功的 DDL 会残留，修复脚本必须重新盘点生效范围（runbook #流程固化）。

## ADR-11 一致性巡检作为发布门禁
- 46 段 SQL 断言（汇总=明细、状态机终态合法、押金余额=流水和），0 行输出才放行。
- 定位：比 UI 测试更便宜的财务不变量回归。

## ADR-12 一次性测试账号隔离守卫类规则
- 日结锁定等"历史状态影响行为"的规则上线后，回归套件改用每轮动态创建的一次性收费员（POST /system/users），固定账号的历史状态不再污染测试；连带消灭硬编码姓名过滤。

## ADR-13 UI 自动化用 Playwright 独立 Chromium
- 真实输入管线才能驱动 Element Plus（内层遮挡/浮层），IAB 注入事件不可靠；混合模式 = API 造数 + Playwright 断言关键交互。
