# 医院信息系统（HIS）系统设计白皮书

> 求职作品集技术文档 ｜ 单体优先的模块化单体架构 ｜ Spring Boot 3.2 + MyBatis-Plus 3.5.5 + Vue 3.4 + MySQL 8 + Redis 5
> 所有数字均来自仓库内可复跑的测试与脚本，验证方式随文标注。

## 1. 项目定位

一套覆盖门诊、住院、急诊五大中心、手术麻醉、检验、血库、药房药库、医保、病案、公卫、体检、运营分析等 **18 个业务模块** 的医院信息系统。定位不是玩具 CRUD，而是把医院信息系统的**核心难点**做扎实：

- 多角色协同下的**业务状态机**（就诊、住院、手术、危急值、传染病报告……十余条单向状态链）
- **资金路径的正确性**（收费/退费/日结/押金抵扣，幂等与对账）
- **并发正确性**（库存扣减、槽位占用、同患者并发入院）
- **合规与安全**（RBAC 数据范围、PHI 双层脱敏、操作留痕）
- **可运维性**（一键部署、一致性巡检、备份恢复演练、故障降级）

## 3. 架构总览

```
浏览器（Vue3 + Element Plus，RBAC 动态菜单 + v-perm 指令）
   │  nginx（静态资源 no-cache、安全响应头、API 反代）
   ▼
Spring Boot 模块化单体
   ├─ modules/*：18 个业务模块（controller / service / app / entity / mapper）
   ├─ app 层：跨模块应用服务（InpAppService / ClinicAppService / PatientAppService …）
   │          ——状态机变更全部收敛到 app 层，模块间不直连彼此的 mapper
   ├─ infrastructure：JwtAuthFilter → SessionService（Redis）→ @Idempotent 切面 → IdGenerator
   └─ common：R 响应体 / ErrorCode 错误码字典 / 全局异常 / 审计注解
   ▼
MySQL 8（Flyway V1~V38） + Redis 5（会话 / 幂等 / 登录限流 / 单号计数）
```

**模块化单体的取舍**：拒绝微服务，理由是部署目标为单机医院演示环境，拆分只会引入分布式事务与运维成本；但用 app 层 + 独立 mapper 边界保持了"逻辑微服务"的演化能力——任一模块 future 拆出时只需替换 app 层调用为 RPC。

## 4. 核心机制与实现

### 4.1 业务状态机：前态校验 + 条件更新 + 唯一索引三层防线

十余条状态链（就诊 10→20→30、住院 10→20→30、手术 10→20→30→40→50→60、危急值 10→20→30→40、传染病 10→20→30→40）全部收敛在 app 层。防并发三件套：

1. **前态校验**：状态跳变前校验前置状态；
2. **条件更新**：执行单推进用 `UPDATE ... WHERE status=旧值` 影响行数判定（并发双击只有一人成功）；
3. **唯一索引兜底**：预检窗口内的竞态由数据库唯一键拦截（如 `uk_bill_visit` 防重复收费、`uk_emc_visit_triage` 防重复登记、`uk_schedule_slot2` 防手术槽位双占），DuplicateKeyException 转译为业务错误码。

### 4.2 幂等：三段式设计（`@Idempotent` 切面）

`SETNX idem:{userId}:{key} = 请求摘要(SHA-256)`，TTL 24h：
- 命中且摘要一致 → 返回首次响应快照；摘要不同 → A0005；
- **失败释放**：业务异常时删除幂等键（否则失败 key 残留 24h，用户重试永远被拦）；
- **Redis 故障 fail-open**：降级放行，由数据库唯一约束兜底——幂等是优化，正确性锚在 DB。

### 4.3 资金路径：对账驱动的收敛

- 门诊收费：账单表对 `visit_id` 唯一，并发双收银员后到者撞唯一键转 B3001；
- 出院结算：`uk_bill_adm` 防双结算；**标记收窄**——只把账单实际包含的费用标记已结，标记后复查残留未结费用，有则同事务回滚要求重试（防"结算窗口期新增费用被标记已结却从未入账单"的资损）；
- 日结：`(settle_date, cashier_id)` 唯一；**日结锁定**——本人当日已日结后收费/退费/住院结算一律拒绝，否则交易落在任何日结之外造成对账永久失真；
- 退费：行锁序列化 + 明细级可退余量 + 处方整方退规则 + 已发药先退药门禁。

### 4.4 并发正确性：专项测试固化

`concurrency_test.py` 12 项并发断言：物资并发领用不超卖（行锁 + 条件更新）、同袋并发发血恰一次成功、并发取消/配血终态一致、**同患者并发双入院恰一笔成功**（患者行锁串行化）。

### 4.5 发号器：降级号段 + 恢复补偿

`{前缀}{yyyyMMdd}{6位}` 由 Redis INCR 计数。部分降级（超时抖动）时切换**实例内高基址号段（500001+）**与正常号段物理隔离，避免与宕机前历史号撞号；Redis 恢复后若计数回退（重启丢失），**补偿跳过降级号段**再继续。单测模拟"正常→降级→恢复回退"全程无撞号。

### 4.6 安全：纵深三层

1. **垂直权限**：RBAC（用户-角色-权限），261 端点 `@PreAuthorize` 全覆盖（扫描器审计），前端 v-perm 只是体验层，后端才是防线；
2. **横向数据范围**：收费员仅本人经办账单/退费/日结（列表与**详情**双重过滤——列表过滤≠详情过滤，detail 裸查是本轮 IDOR 修复点）；审计日志按角色收敛；
3. **PHI 双层脱敏**：服务端 `toResponse()` 统一脱敏（手机号 3+4、身份证 4+4、身份证哈希存储），前端 mask.ts 第二道防线；登录限流（连续失败锁定 + 成功清零）+ 全量登录/操作日志留痕。

### 4.7 韧性：Redis 降级演练（七探针实录）

Redis 承担会话/幂等/限流/计数。停机演练结论：**Redis 是认证硬单点**（宕机期合法令牌 401、登录 C9001），幂等/发号的降级路径仅在部分降级时可达；优雅停机持久化会话，恢复后旧会话回归、连接池有秒级重连窗口。全部结论固化为 runbook 演练实录。fail-open/fail-closed 的选择逐触点显式化：限流 fail-open、会话 fail-closed、幂等 fail-open+DB 兜底、发号降级+补偿。

### 4.8 急诊五大中心：时间轴即质控

分诊→救治登记（一对一带唯一索引）→节点录入（字典内/属当前中心/不重复/不早于登记时刻四重校验）→**录入即达标判定**（自动计算与登记时刻差值比对目标时限）→达标率按中心/节点/月聚合。节点字典可配置，认证标准调整不改代码。

### 4.9 数据库工程

Flyway V1~V38 只增不改（失败重放防护：已成功 DDL 残留的重新盘点流程）；索引审计 EXPLAIN 驱动（患者电话前缀检索 5 万行全扫→162 行、收费员/日结复合索引）；一致性巡检 46 段 SQL 对账（汇总=明细、状态机终态、余额=流水）。

## 5. 工程化

- **一键部署** `deploy/deploy.sh`：停服→备份 jar→替换→启动→健康检查→Flyway 校验→**旧前端产物引用闭包回收**；
- **CI**（GitHub Actions）：单测 → 前端构建 → 一致性巡检 → 9 套 e2e 全量 fail-fast；
- **备份**：本地每日 + 异盘 robocopy 同步，恢复演练实测 RTO ≈ 60s；
- **经验沉淀**：50+ 轮查验的模式化总结 `docs/lessons/bug-patterns.md`（HTTP 头 ASCII 纪律、双层确认弹窗、槽位类测试、快照式报表的锁语义……），运维手册 `ops-runbook.md`。

## 6. 已知边界（诚实清单）

- 单机演示部署：集群化需 Redis 哨兵 + 会话外置策略重审；
- 支付通道为 MOCK（结构已留接口位）；
- 微服务拆分未做（有意取舍，见 §3）；
- 互联网医院暂缓，待外部条件（对接资质、专线）具备再启动；
- **区域平台上报已按"五期-lite"落地**（第八十二轮）：RPT 模块 + rpt_upload 表（V44/V45/V50），
  MOCK 网关承载传染病报告卡/病案归档/出院结算三类触发 → 30s 调度投递（失败指数退避，
  手动通道优先新行防队头阻塞）→ QY 受理号回执 → 重试耗尽转失败并事件告警 → 手动重报回队。
  与真实区域平台对接（WS/T 标准、专线）时仅需实现 RptService 的 HTTP 投递分支，留接口位。
