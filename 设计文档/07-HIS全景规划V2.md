# 07 HIS 全景规划 V2

版本：V1.0 ｜ 定位：在《医院信息系统技术指导文档》一期之上，建立覆盖全院的全景系统规划，作为二期~三期立项与优先级排序的顶层输入
依据：全景系统分类评审（7 大类框架保持，补充 14 个缺失项、收敛 4 处重复归属、新增闭环横切与分期视图）

---

## 1. 总体框架

**两条主线不变**：患者就医闭环 ＋ 医院运营管理。
**三个视图**：① 系统清单（§3，空间视图）；② 医疗安全闭环横切（§4，流程视图）；③ 分期路线图（§5，时间视图）。
**四个合规锚点**（贯穿标注）：【EMR评级】电子病历应用水平分级、【互联互通】标准化成熟度测评、【等保三级】网络安全等级保护、【国考】三级公立医院绩效考核；另以【法定】标注法定义务类（传染病直报等）。

排优先级原则：**法定义务 > 评审强制 > 运营增强**。

## 2. 一期工程在全景中的位置

| 全景域 | 一期覆盖内容 |
|---|---|
| 门急诊管理系统（子集） | 患者建档、挂号/退号、候诊、门诊收费/退费、日结 |
| 药事管理系统（门诊药房部分） | 处方审核、发药/退药、库存批次/预警（无药库/PIVAS） |
| 数据底座（原型） | 统一权限审计、操作日志、统计报表、e2e 验收 |
| 未覆盖（后续分期） | 住院、EMR、护理、医技（LIS/PACS）、病案、医保、集成平台等 |

## 4. 医疗安全闭环横切视图（跨系统流程，防断点）

| 闭环 | 发起 | 流转节点 | 关闭点 | 涉及系统 |
|---|---|---|---|---|
| 医嘱闭环 | 医生（EMR） | 药师审核（药事）→ 护士核对（护理）→ 执行/发药 | 执行留痕 | 一期已建门诊段；住院段二期 |
| 危急值闭环 | LIS/PACS | 平台推送 → 医护确认（移动端提醒） | 处置记录留痕 | 三期医技 + 二期平台 |
| 输血闭环 | 医生 | 血库配血 → 双人核对 → 输注观察 | 输血反应记录 | 三期 |
| 手术安全核查 | 病房 | 麻醉前/切皮前/离室前三方核查 | 核查单签名 | 三期 ORIS |
| 传染病上报 | 临床（EMR 诊断触发） | 公卫科审核 | 疾控直报回执 | 二期起【法定】 |
| 标本闭环 | 医生申请 | 采集 → 条码 → 送检 → 接收 | 检测完成 | 三期 LIS |
| 不良事件闭环 | 任何员工 | 上报 → 质控分派 → 整改 | 闭环确认 | 二期起 |

> 每个闭环须在集成平台定义**标准事件与状态机**，各系统只实现节点，平台负责全程追溯——这是消除"单系统视角断点"的关键。

## 5. 分期路线图

| 分期 | 范围 | 合规目标 |
|---|---|---|
| **一期（已完成 ★）** | 门诊闭环：建档/挂号/医生站/收费/门诊药房/报表/权限审计；e2e 40 项、性能 §7 达标 | 打底 |
| **二期（建议）** | 住院管理、EMR（住院病历+质控）、医嘱闭环住院段、护理+移动护理、病案管理、本地医保结算接口；**同步立标准**：集成平台雏形 + EMPI + 集成事件规范（§4 闭环清单为事件目录） | 电子病历 3~4 级 |
| **三期** | LIS、PACS/RIS、手术麻醉、药库+PIVAS、体检、急诊五大中心、HR/物资/绩效（含国考监测） | 互联互通测评 |
| **四期+** | 互联网医院、CDSS 全面化、AI 应用、区域互认深化、信创迁移 | 电子病历 5 级+ |

排序原则：法定义务与评审强制先行；平台标准（EMPI/事件规范）先行于新系统建设，避免后期翻账。

## 6. 二期功能清单（与一期工程对齐）

沿用一期技术栈与模块化单体边界（新增模块 `inp_` 住院、`emr_` 电子病历、`nur_` 护理、`mrc_` 病案、`medins_` 医保）：

| 工作包 | 内容 | 与一期的衔接 |
|---|---|---|
| WP2.1 集成平台雏形 + EMPI | 患者主索引服务（一人多卡多号归一）、患者合并、事件订阅规范（以 §4 七个闭环为事件目录） | 复用一期 pat_patient 与建档流程，EMPI 以 patient_no 为主键延伸 |
| WP2.2 住院管理 | 入院登记、床位/床位状态机、押金、每日费用清单（一日清）、出院结算、转科 | 收费/退费/日结复用一期 billing 模块（visit 扩展为住院就诊类型） |
| WP2.3 EMR 住院病历 | 大病历结构化书写、模板、质控规则（缺项/时限）、知情同意 | 门诊病历（cli_visit）结构保留，新增住院文书域 |
| WP2.4 医嘱闭环住院段 | 长期/临时医嘱、成组医嘱、皮试、停嘱；护士核对执行 | 复用一期处方审核/发药链路，医嘱模型泛化 |
| WP2.5 护理与移动护理 | 排班、体征采集、PDA 执行与扫码 | 复用权限审计与单号生成等底座 |
| WP2.6 病案管理 | 病案首页质控、ICD 编码、归档与借阅 | EMR 完成后自动归档 |
| WP2.7 本地医保结算接口 | 挂接本地医保 SDK 的结算/对账（模拟+联调双通道） | 复用一期收费结算的"模拟支付防腐层"接口位 |

二期验收场景建议：入院 → 医嘱 → 护士执行 → 费用一日清 → 出院结算 → 病案归档 → 医保对账，连续三次成功（对齐一期 §9 验收风格）。

## 7. 边界与风险声明

- 本规划为**顶层蓝图与优先级框架**；各分期启动前仍需按一期模式产出独立设计文档并评审。
- 全景覆盖不等于全部自研：OA、后勤、体检等建议成熟产品选型 + 接口对接（经集成平台）。
- 医保/疾控/卫健委接口以当地平台规范为准，联调周期须预留。
- 继续遵守指导文档 §10：正式生产前完成合规评估、等保定级备案与信息科审批。
