## 一期系统一句话定义

面向中小型医院/教学演示的模块化单体 HIS：打通 **患者建档 → 挂号 → 医生接诊（病历/诊断/处方/检查申请）→ 收费 → 药师审核发药 → 统计查询与退药退费** 的核心闭环，角色覆盖管理员、医生、收费员、药师、对账员。

## 关键设计决策摘要

| 决策点 | 结论 | 理由 |
|---|---|---|
| 架构形态 | 模块化单体（Maven 单工程、按模块分包），预留服务边界 | 指导文档 §2.2，无明确性能/组织需要不引入微服务 |
| 收费时点 | 挂号费、处方费、检查费统一挂到"就诊"，收费工作站一次性汇总收费；不发预交金 | 与指导文档 §9 验收场景顺序一致（开处方后才收费），实现最简 |
| 发药前置条件 | 处方"审核通过"且"已收费"且库存充足，三者由后端事务内复核 | §6 阶段三验收：未收费不可发药、库存不足不能发药 |
| 防重复发药 | `phr_dispense_order.prescription_id` 唯一索引 + 处方状态行级校验 | 数据库层兜底，杜绝并发重复发药 |
| 金额与数量 | DECIMAL(10,2)，后端按明细重算合计，不信任前端金额 | §4.3"金额使用定点小数，禁止浮点" |
| 幂等 | 提交类接口强制 `X-Idempotency-Key`，Redis 记录首响应 24h | §5.4、§7"重复提交"四类测试之一 |
| 审计 | 关键操作 AOP 写 `sys_operation_log`（append-only），敏感字段脱敏 | §7 审计、安全要求 |
| 二期边界 | 住院、医保、检验/影像对接、电子签名、AI 辅助等一律不做 | §3.2 明确排除，避免范围蔓延 |
